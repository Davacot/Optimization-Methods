# Лабораторная работа №1  
**Дисциплина:** «Методы оптимизации. Линейное программирование»  
**Вариант:** 6 — план выработки электроэнергии станциями (горизонт 24 часа)

## 1) Постановка задачи

Требуется минимизировать суммарные затраты генерации за сутки при:
- покрытии почасового спроса;
- ограничениях установленной мощности станций;
- суточных лимитах выработки (топливо/вода).

Модель используется для диспетчеризации выработки по 5 станциям:
`NPP`, `Coal`, `CCGT`, `Hydro`, `Peaker`.

## 2) Формальная модель

### Множества
- `I` — множество станций, `|I| = 5`;
- `T` — множество часов суток, `|T| = 24`.

### Параметры
- `c_i` — удельная стоимость выработки станции `i`, у.е./MWh;
- `Cap_i` — почасовая мощность станции `i`, MWh/ч;
- `D_t` — спрос в час `t`, MWh;
- `L_i` — суточный лимит станции `i`, MWh.

### Переменные
- `p_{i,t} >= 0` — выработка станции `i` в час `t`, MWh.

### Целевая функция
\[
\min \sum_{i \in I}\sum_{t \in T} c_i p_{i,t}
\]

### Ограничения
1. Покрытие спроса (для каждого `t`):
\[
\sum_{i \in I} p_{i,t} \ge D_t
\]
2. Почасовая мощность станции:
\[
p_{i,t} \le Cap_i, \;\forall i,t
\]
3. Суточный лимит станции:
\[
\sum_{t \in T} p_{i,t} \le L_i,\;\forall i
\]

## 3) Реализация и инструменты

- Язык: Python 3.
- Солвер: HiGHS через `scipy.optimize.linprog`.
- Выбранный алгоритм: `highs-ds` (dual simplex), параметр запуска `--method highs-ds`.
- Presolve: включён (`presolve=True`, по умолчанию; можно отключить `--no-presolve`).
- Библиотеки: `numpy`, `pandas`, `matplotlib`, `scipy`.
- Модель и данные разделены:
  - данные: `data/variant6_base_data.json`,
  - модель: `src/lp_model.py`.
- Генерация данных детерминирована:
  - формула ТЗ: `seed = 10000 + 100*Q + N`,
  - либо явный запуск с `--seed`.
- Запуск одной командой: `python run_lab1_variant6.py --n <N> --q <Q> --method highs-ds`.

## 4) Статус решения и независимая проверка

Для всех сценариев получен статус `optimal` (HiGHS Status 7).  
Интерпретация статусов в коде:
- `optimal` — найден оптимум;
- `infeasible` — нет допустимого плана;
- `unbounded` — целевая функция не ограничена;
- `iteration_or_time_limit` — достигнут лимит;
- `solver_error` — численная/внутренняя ошибка решателя.

Независимая проверка (NumPy, без обращения к объекту солвера) подтвердила:
- допустимость решений (`max_constraint_violation = 0.0 <= 1e-7`);
- корректный пересчёт целевой функции.

Файл проверки: `outputs/verification_results.csv`.

Суммарная суточная выработка по станциям:
- `NPP`: 7200.0 MWh
- `Hydro`: 1920.0 MWh
- `CCGT`: 3713.6 MWh
- `Coal`: 213.36 MWh

Интерпретация:
- в базовом плане полностью загружены дешёвые источники `NPP` и `Hydro`;

- `Coal` включается ограниченно в часы высокой нагрузки;
- дорогая пиковая станция `Peaker` не используется (нулевая переменная имеет предметный смысл: высокая себестоимость).

## 7) Теневые цены и сопоставление со сценариями

По `outputs/shadow_prices_base.csv`:
- для дневного лимита `Hydro` теневая цена = **12.0** у.е./MWh (ограничение активно);
- для спроса в пиковые часы (18–22) теневая цена = **42.0** у.е./MWh, в остальные часы чаще **36.0**.

Экономический смысл:
- +1 MWh доступной гидроэнергии снижает целевую функцию примерно на 12 у.е. в окрестности базового плана;
- в часы 18–22 дополнительный спрос дороже, так как активируется более дорогая маржинальная генерация.

Проверка прогноза на дефицитном сценарии:
- снижение лимита `Hydro` на 384 MWh по локальной оценке даёт прирост порядка `384 * 12 = 4608` у.е.;
- фактически получили +5433.60 у.е., что больше локальной оценки из-за перехода в другой режим активных ограничений.

## 8) Допущения и ограничения модели

Учебные упрощения:
- нет ограничений на скорость набора/сброса мощности (ramp rates);
- нет минимального времени включения/выключения блоков;
- отсутствуют сетевые ограничения по передаче;
- неопределённость спроса не моделируется.

## 9) Практическая реализуемость

Решение пригодно как базовая LP-оценка экономичной диспетчеризации на сутки.  
Для промышленного внедрения требуется расширение до MILP/UC-модели с бинарными переменными включения блоков, динамикой режимов и ограничениями сети.
